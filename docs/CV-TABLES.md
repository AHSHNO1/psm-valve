# راهنمای جدول Cv محصولات

این قابلیت به سایزینگ اجازه می‌دهد به‌جای «جدول Cv عمومی»، از **Cv واقعی هر سری محصول PSM** استفاده کند و سایز پیشنهادی را با نام و شمارهٔ سری درست نشان دهد.

---

## ۱. از کجا وارد کنم؟

پنل مدیریت → گروه **مهندسی** → **جدول Cv سایزینگ**
مسیر: `/admin/cv-tables`

برای هر سری یک کارت هست. کارت را باز کنید، سایزها را وارد کنید و «ذخیره» بزنید. تغییر بلافاصله در صفحهٔ سایزینگ اعمال می‌شود (بدون بیلد).

## ۲. چه عددی وارد کنم؟

- **Cv کاتالوگی در ۱۰۰٪ بازشدگی** و برای **ترم خطی (Linear)**.
- Cv بدون واحد است؛ همان عددی که کاتالوگ سازنده می‌دهد (تعریف: gpm آب در ۶۰°F با ۱ psi افت).
- اگر ترم Equal% دارید، Cv نامی همان سایز را وارد کنید (مقدار ۱۰۰٪).
- اگر فقط بخشی از سایزها را دارید، همان‌ها را وارد کنید؛ بقیه لازم نیست.

## ۳. قالب ورود

دو راه:

1. **ردیف‌به‌ردیف:** «+ افزودن سایز» → `DN50` و `45`
2. **چسباندن گروهی:** کادر «چسباندن چند سایز» را باز کنید و در هر خط:

```
DN50, 45
DN80, 90
DN100, 150
```

3. **ورود گروهی چند سری (کپی از اکسل):** کادر «ورود گروهی از اکسل» را باز کنید و در هر خط `سری, DN, Cv` بگذارید:

```
51000, DN50, 45
51000, DN80, 90
46000, DN50, 120
```

برای خط‌های دوستونی (`DN50, 45`) از فیلد «سری پیش‌فرض» استفاده می‌شود. ستون‌ها با `,` یا `;` یا `=` یا Tab جدا می‌شوند و «ذخیرهٔ همه» برای هر سری یک درخواست جدا می‌فرستد؛ خط‌های نامعتبر نادیده گرفته و گزارش می‌شوند.

جداکنندهٔ `,` یا `;` یا `=` یا فاصله قابل قبول است. قالب `DN` الزامی است و Cv باید عددی مثبت باشد.

## ۴. سایزینگ چطور انتخاب می‌کند؟

1. Cv محاسبه‌شده (با احتساب `Fp` در صورت وارد کردن DN لوله) گرفته می‌شود.
2. **حاشیهٔ طراحی:** Cv هدف = `Cv محاسبه‌شده ÷ 0.8` تا شیر در حداکثر دبی حدود ۸۰٪ باز باشد.
3. در بین سری‌های دارای جدول، ابتدا خانواده‌های کنترلی (گلوب/روتاری/دما بالا) بررسی می‌شوند.
4. کوچک‌ترین Cv که از هدف بزرگ‌تر یا مساوی است انتخاب می‌شود.
5. اگر هیچ سایزی به هدف نرسد، نزدیک‌ترین Cv بالاتر از نیاز انتخاب می‌شود و بازشدگی بالای ۸۰٪ در نتیجه دیده می‌شود.
6. اگر هیچ جدولی برای آن نیاز موجود نباشد، سایزینگ به **جدول عمومی** برمی‌گردد و برچسب «Cv عمومی» را نشان می‌دهد.

## ۵. ساختار فایل داده

`data/valve-cv-tables.json`

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-10-17T20:01:36.811Z",
  "series": {
    "51000": {
      "sizes": [
        { "dn": "DN50", "cv": 45 },
        { "dn": "DN80", "cv": 90 }
      ],
      "updatedAt": "2026-10-17T20:01:36.811Z"
    }
  }
}
```

- کلید `series` همان شمارهٔ سری محصول است (مثل `51000`).
- `dn` باید `DN` + عدد باشد؛ `cv` عددی مثبت.
- نوشتن **اتمیک** است (فایل موقت + rename) و **فقط سری جاری** بازنویسی می‌شود؛ دو تب هم‌زمان دادهٔ هم را پاک نمی‌کنند.

## ۶. API

| متد | مسیر | دسترسی | بدنه |
|---|---|---|---|
| GET | `/api/cv-tables` | ادمین | — |
| PUT | `/api/cv-tables` | ادمین | `{ "series": "51000", "sizes": [{"dn":"DN50","cv":45}] }` |
| DELETE | `/api/cv-tables?series=51000` | ادمین | — |

خطاهای اعتبارسنجی با `400` و آرایهٔ `errors` برمی‌گردند. بدون نشست معتبر `401` است.

## ۷. عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| برچسب «Cv عمومی» | سری جدول ندارد یا Cv آن کمتر از نیاز است | جدول همان سری را تکمیل کنید |
| خطای «قطر باید مثل DN50 باشد» | قالب DN رعایت نشده | `DN50` بنویسید، نه `2 inch` |
| بازشدگی بالای ۸۰٪ | بالاترین سایز ثبت‌شده کافی نیست | سایز بزرگ‌تر را وارد کنید یا شیر بزرگ‌تر انتخاب شود |
| تغییرات دیده نمی‌شود | صفحهٔ سایزینگ را رفرش کنید | داده در همان درخواست بعدی خوانده می‌شود |

## ۸. نکتهٔ مهندسی

این جدول فقط **Cv** را نگه می‌دارد. برای انتخاب نهایی، محدودهٔ فشار/دما، متریال بدنه و ترم، کلاس نشتی (FCI 70-2) و شرایط کاویتاسیون هم باید بررسی شود. خروجی ابزار «پیشنهاد» است، نه تأییدیهٔ خرید.

## ۹. دادهٔ مرجع کاتالوگ (منحنی مشخصهٔ ذاتی)

از نسخهٔ جاری، سایزینگ می‌تواند به‌جای «یک Cv برای هر قطر»، **نردبان ترم‌ها و منحنی مشخصهٔ ذاتی** هر سری را از کاتالوگ شرکت استفاده کند.

| مورد | مسیر / ابزار |
|---|---|
| فایل مرجع (فقط‌خواندنی، در گیت) | `data/valve-cv-catalog.json` |
| ساخت/به‌روزرسانی از اکسل | `python scripts/import-cv-xlsx.py` (یا `npm run cv:import`) |
| بررسی فایل اکسل پیش از ورود | `python scripts/inspect-cv-xlsx.py VALVE_CV.xlsx --summary --validate --analyse` |
| بازبینی پیشنهادها روی محصولات واقعی | `node scripts/catalogue-coverage.mjs` (یا `npm run cv:coverage`) |
| ویرایش دستی (اولویت بر کاتالوگ، فقط همان DN) | پنل `/admin/cv-tables` |

ساختار هر سری در فایل مرجع:

```json
"51000": {
  "sizes": [
    {
      "nps": 8, "dn": "DN200", "dnMm": 200, "cvMax": 500,
      "trims": [
        { "cv": 360, "characteristic": "equal", "ratio50": 0.242, "rangeability": 40,
          "curve": [9, 21, 39, 60, 87, 135, 200, 269, 326, 360] },
        { "cv": 500, "characteristic": "linear", "ratio50": 0.5, "rangeability": 10,
          "curve": [50, 100, "…", 500] }
      ]
    }
  ]
}
```

- `curve` = Cv در ۱۰، ۲۰، … ۱۰۰ درصد بازشدگی (۱۰ نقطه).
- `characteristic`: `equal` (درصدی)، `modified` (اصلاح‌شده)، `linear`، `quick` (بازشدگی سریع) — بر پایهٔ نسبت Cv در ۵۰٪ به مقدار نامی.
- `ratio50` و `rangeability` برای بازبینی مهندسی نگه داشته می‌شوند.

### منطق انتخاب با منحنی

1. بازشدگی هر کاندیدا با **معکوس‌سازی منحنی** حساب می‌شود (نه فرض خطی).
2. شرط حاشیهٔ طراحی: `Cv منحنی در ۸۰٪ ≥ Cv موردنیاز`.
3. اولویت: کوچک‌ترین Cv نامی (تنگ‌ترین تناسب)، سپس مشخصهٔ ترجیحی
   (**درصدی → اصلاح‌شده → خطی → بازشدگی سریع**)، سپس خانوادهٔ کنترلی، سپس سایز کوچک‌تر.
4. اگر هیچ ترمی حاشیهٔ ۸۰٪ را رد نکند، تنگ‌ترین تناسب با هشدار «بازشدگی بیش از ۸۰٪» برمی‌گردد.

### قواعد ادغام با جدول دست‌نویس

- جدول ادمین **فقط همان DN** را جایگزین می‌کند؛ بقیهٔ ترم‌های کاتالوگ برای همان سری حفظ می‌شوند.
- Cv دست‌نویس بدون مشخصه، با **فرض خطی** محاسبه می‌شود و در گزارش با برچسب «فرض خطی (بدون منحنی)» دیده می‌شود.
- فایل مرجع در پنل ویرایش نمی‌شود؛ منبع آن کاتالوگ شرکت است.

### قابلیت ردگیری داده

بخش‌های `source`، `stats`، `repairs` و `warnings` در فایل مرجع ثبت می‌شوند. مغایرت‌های تایپی منبع
(مقدار خارج از روند صعودی) با درون‌یابی و **ثبت در `repairs`** اصلاح می‌شوند تا قابل بازبینی باشند.
تست `tests/cv-catalog.test.mjs` کیفیت این داده را در هر اجرای `npm test` بررسی می‌کند.

## ۱۰. کار با پنل `/admin/cv-tables`

صفحه بر اساس **سری محصول** ساخته می‌شود (نه هر محصول جدا) تا محصولات هم‌سری یک کارت بگیرند.

### کارت پوشش داده

بالای صفحه درصد پوشش و شمارش «کدام سری داده دارد» را نشان می‌دهد؛ «سری مؤثر در سایزینگ» یعنی سری‌هایی که
محصولشان بازهٔ سایز خوانا دارد و در ابزار سایزینگ می‌آیند (همان شرط `buildSizingCatalog`). دو دکمهٔ
**خروجی JSON** و **کپی JSON** هم همان‌جا هستند.

### برچسب وضعیت هر سری

| برچسب | معنا |
|---|---|
| کاتالوگ + دست‌نویس | هم دادهٔ مرجع کاتالوگ دارد، هم DN ذخیره‌شده در پنل |
| کاتالوگ (با منحنی) | دادهٔ کامل کاتالوگ با منحنی مشخصهٔ ذاتی؛ ورود دستی لازم نیست |
| جدول دست‌نویس | فقط DNهای همین پنل (بدون منحنی، محاسبه با فرض خطی) |
| بدون داده | سایزینگ برای آن «Cv عمومی» نشان می‌دهد |
| خارج از سایزینگ | محصولش بازهٔ سایز خوانا ندارد؛ در ابزار سایزینگ نمی‌آید |
| سری نامعتبر | شناسهٔ سری با قاعدهٔ سرور (`^[0-9A-Za-z/.-]{1,24}$`) نمی‌خواند؛ قابل ذخیره نیست |

### داخل کارت سری

- **افزودن سایز / حذف سایز** با اعتبارسنجی زنده (همان پیام‌های سرور) و خطای هر ردیف زیر همان ردیف.
- **چیپس سایزهای کاتالوگ** (کلیک = افزودن/به‌روزرسانی همان DN با `cvMax` کاتالوگ) و
  **بارگذاری از کاتالوگ** برای پر کردن کل فرم از دادهٔ مرجع.
- **چسباندن سریع سایزها** برای همان سری (کپی دو ستونی از اکسل).
- **حذف جدول** این سری (بازگشت به دادهٔ کاتالوگ یا «Cv عمومی»).
- بستن کارت بدون «ذخیره»، تغییرات ذخیره‌نشدهٔ فرم را دور می‌ریزد.

### فیلتر و جست‌وجو

فیلترها: همه · بدون داده · با کاتالوگ · جدول دست‌نویس · فعال در سایزینگ — به‌همراه جست‌وجو روی
شمارهٔ سری و نام فارسی/انگلیسی محصول.

### پشتیبان‌گیری و انتقال

«خروجی JSON» فایل `valve-cv-tables.json` را با ساختار `{ schemaVersion, exportedAt, series }` می‌سازد و
«ورود فایل JSON» همان ساختار (یا خروجی خام `data/valve-cv-tables.json`) را می‌خواند؛ هر سری یک PUT می‌گیرد.
